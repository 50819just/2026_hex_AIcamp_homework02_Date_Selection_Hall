# Primary User Journey

狀態：draft  
最後更新：2026-08-13

## Journey 目標
- 讓使用者理解服務分類、費用呈現方式與人工確認流程，最後提交預約申請。
- 送出後讓使用者知道申請已送出，但尚未代表正式預約成立。

## Homepage Conversion Narrative（MVP Product / UX Decision）
- Understand：知道玄機堂是人工擇日與相關傳統服務。
- Service：找到自己的事件與服務分類。
- Trust：理解老師人工確認、事前溝通與真實服務方式。
- Process：知道提出需求後會經過哪些步驟。
- Price：理解參考價格、個案報價與到場費用原則。
- FAQ：消除送出前的疑問。
- Action：開始預約、LINE 詢問或電話聯絡。

## 步驟拆解
1. 使用者進入首頁，理解玄機堂提供擇日與相關諮詢服務。
2. 使用者先看到婚嫁、入宅／搬遷、新生兒等主要人生事件，再看到神明／祖先、宅事／到場與其他需求；不確定時可選「其他擇日需求」。此為 IA／UX 假設，不代表熱門排行。
3. 使用者查看服務情境、資料需求與價格狀態；婚嫁可先看參考區間，其他服務可能顯示依個案確認。
4. 使用者先填寫 Base Information，再依服務類型填寫 `Conditional Optional Fields`。
5. 使用者提供希望辦理期間／候選日期，並可另外填寫方便聯絡時間。
6. 使用者閱讀資料使用說明並勾選必填 Checkbox 後，送出預約申請，看到「預約申請已送出」。
7. 申請資料經 Google Apps Script 寫入私有 Google Sheet，初始狀態為 `New／待確認`；可另發送 Email 新申請通知。
8. 老師人工確認需求類型、基本資料、是否承接、服務方式、費用與日期／安排，再透過 LINE 或電話聯繫；不承諾固定回覆時間。
9. 雙方完成確認後，Booking Request 才轉為 Confirmed Case / Appointment；此成立條件為 `Proxy Assumption`，仍待業主最終確認。
10. 老師依案件確認交付內容、交付方式與處理時間。
11. 服務完成後依事前約定付款，不經網站 Checkout。

## 使用者疑問
- 玄機堂是否有我需要的服務？
- 婚嫁價格是否為正式固定價格？
- 外縣市、到場或多地點是否需要另外報價？
- 送出申請後是否代表預約成立？
- 需要準備哪些出生資料、地址或其他資訊？
- 老師會透過 LINE 還是電話聯繫？
- 哪些服務需要提供到場地址或交通資訊？
- 送出後什麼時候才算正式案件？
- 最後會收到什麼服務內容？需要多久完成？

## 關鍵轉換點
- 首頁服務分類 → 服務詳細內容。
- 價格資訊 → 預約申請。
- 預約申請送出 → 人工確認。
- 費用與日期確認 → 正式預約安排。
- Booking Request → 人工確認 → Confirmed Case / Appointment。
- 服務確認 → 交付內容／方式／時程說明 → 完成服務。
