# 玄機堂擇日舘｜測試與畫面驗收

最後更新：2026-08-14

## 基礎驗證

```bash
npm run build
npm run lint
```

## 視覺與 RWD 驗收

每次有 UI 功能改動，至少在以下 viewport 檢查：

| Breakpoint | Viewport | 必查項目 |
| --- | ---: | --- |
| Desktop | 1440px | Header、12-column 版型、卡片列數、付款摘要 |
| Tablet | 1024px | 導覽簡化、兩欄轉換、Stepper、長文與付款狀態 |
| Mobile | 375px | menu、單欄、表單觸控區、固定 CTA、無水平 overflow |

必查：Logo 色彩與比例、文字換行、鍵盤 focus、按鈕 disabled／loading、圖片裁切、無障礙標示、表單錯誤與狀態頁文案。

## 產品流程驗收

1. Booking 固定顯示 4 Steps。
2. 第一次送出只顯示「預約申請已送出」，不顯示預約成功、不導向付款。
3. 付款頁僅代表人工確認後的預約訂金階段。
4. 成功狀態顯示服務總價、訂金與尾款；NT$5,000 範例需為訂金 NT$800、尾款 NT$4,200。
5. 失敗／取消不可顯示付款成功或服務已完成。

## Demo 素材驗收

- 人物卡需有「示意人物」標示。
- 個案卡需有「示範個案」或「情境示例」標示。
- 裝飾圖不承擔必要流程／價格／規則資訊。
- 詳細規則見 `docs/specs/DEMO_VISUAL_ASSET_SPEC.md`。

## 正式綠界整合（後續）

正式／測試環境串接前，另建立後端測試計畫。不得沿用舊花店／購物車 E2E 流程；驗證基準以 `docs/Spec.md` 的人工確認後訂金流程為準。
