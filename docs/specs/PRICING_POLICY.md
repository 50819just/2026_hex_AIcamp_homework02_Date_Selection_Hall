# PRICING_POLICY.md

狀態：draft  
最後更新：2026-08-13

## 文件目的

本文件用於定義玄機堂擇日舘網站第一版的價格揭露方式、費用呈現原則、改期與退款規則，讓網站在價格資訊上保持透明、安心、可理解。

## 價格揭露原則

- 以透明、安心、可理解為原則。
- 優先揭露起始價格或區間價格，不使用完全模糊的私訊報價說法。
- 若無法公開固定價格，需說明影響價格差異的主要因素。
- 價格說明應與服務介紹、FAQ、預約流程中的資訊一致。

## 第一版價格呈現方式

### MVP 目前採用的價格狀態
- 婚嫁擇日可先顯示 NT$1,500～2,500 作為「參考區間／Mock Reference Price」，不得標示為正式固定價。
- 神明・祖先事宜顯示 NT$8,000 起，為 Spec.md 已確認的前台起始參考價格。
- 2026-08-14 更新：為了讓價格頁每項服務都能先呈現一個數字，新生兒命狀・命名（NT$1,200～2,000）、入宅・搬遷擇日（NT$1,500～2,500）、宅事・到場諮詢（NT$2,000 起）、其他擇日需求與其他服務諮詢（NT$1,500 起）改為顯示 MVP 參考價格，比照婚嫁擇日的 Mock Reference Price 做法，明確標示「MVP 參考價格，非正式固定價目，實際費用由老師依案件確認」。這些數字是依現有已確認區間的難度／情境類比推算，不是業主提供或市場調查得出，正式定價仍待業主確認後才可視為固定價目。
- 外縣市、跨縣市、多地點、老師到場，以及神明／祖先相關特殊案件不自動計價，由人工確認服務費與車馬費等費用。
- 客人通常會先詢問費用；諮詢費、車馬費等相關費用原則上於服務前說明。
- 第一次送出預約申請不付款；老師人工確認服務內容、服務總價與日期／時間後，才進入綠界預約訂金付款。
- 預約訂金採三段級距：服務總價 NT$5,000 以下收 NT$800；NT$5,001～8,000 收 NT$1,200；NT$8,001 以上收 NT$1,600。
- 尾款為服務總價扣除已付預約訂金，付款成功後需向使用者顯示尾款明細。
- 不做購物車、完整服務費一次付清或電商式 Checkout；綠界只處理人工確認後的預約訂金。
- 網站可使用：「服務內容、費用與付款方式將於正式確認案件時說明，並依雙方事前約定辦理。」
- 不承諾固定完成天數、24 小時完成、3 個工作天或其他未經業主確認的 SLA。
- 處理時間可受服務類型、資料完整度、是否需要到場與老師行程安排影響，實際於確認案件時說明。

## 急件規則

- 預約表單可提供「時間較急，希望老師優先確認是否可承接」作為 Urgency Signal。
- 急件標記不代表保證優先處理、一定承接或一定加收費用。
- 急件定義、加急費、不接受的時間範圍與特殊聯絡方式皆待業主確認。

## 修改／改期與費用

- 修改規則依案件進度與變更內容人工確認。
- 老師尚未開始作業前，使用者可盡早聯繫協助更新資料、日期區間或地址；是否影響費用仍待確認。
- 老師已開始擇日、命名或處理案件後，若變更日期條件、主要需求、地點或服務內容，可能需要重新處理、重新安排或重新報價。
- 不預先承諾免費修改、無限次修改或固定修改費。
- 取消、退款與已開始服務後的變更政策仍待確認。

### 建議揭露內容
- 已確認或可作為 MVP Mock 的服務，顯示起始價格或區間價格並標註狀態。
- 尚未確認正式價格的服務，顯示「依個案確認」並說明人工報價情境。
- 是否含前期諮詢。
- 是否提供加急處理。
- 是否可能因需求複雜度而調整。
- 是否有改期費、取消規則與退款條件。

### 不建議做法
- 僅寫「價格私訊洽詢」而完全不提供範圍。
- 使用過度神祕或暗示式說法，讓使用者無法判斷大致成本。
- 各頁面價格說法不一致。

## 價格差異可能因素

- 服務類型不同。
- 需求複雜度不同。
- 是否需要加急處理。
- 是否同時處理多個相關事項。
- 是否有特殊時間壓力或額外確認需求。

## 加急費原則

- 第一版可保留是否提供加急服務的彈性。
- 若提供加急，需明確說明適用條件。
- 若加急費未定，網站上應以「待確認」或「將由人工說明」標記，不自行虛構金額。

## 改期費原則

- 是否收取改期費需明確說明。
- 應定義哪些情況屬於可免費調整，哪些情況會產生額外費用。
- 若尚未有正式規則，需在網站先以保守說法呈現，避免承諾過頭。

## 退款規則原則

- 是否可退款需依服務進度與交付狀態判定。
- 若服務已開始人工處理，退款條件需特別明確。
- 若第一版尚未開放線上付款，也仍需說明取消與費用處理方式。

## 價格頁應包含的資訊

- 服務名稱
- 起始價格或區間價格
- 價格差異原因
- 是否含諮詢
- 改期／取消基本規則
- 特殊情況由人工確認的說明

## Pricing Page Architecture（MVP Product / UX Decision）

價格頁不採傳統固定價目 Table 作為唯一呈現方式，採 `Pricing Cards + Pricing Rules`：

1. Pricing Hero：說明網站提供參考價格，實際費用由老師事前確認。
2. Pricing Cards：服務名稱、簡短說明、Price State、補充 Notes 與 CTA。
3. Special Quote Section：集中說明外縣市、到場、多地點、搬遷、神明／祖先、特殊宅事、急件與需求修改可能需要人工確認。
4. Pricing Process：提出需求 → 老師確認 → 事前說明價格 → 雙方確認 → 服務。
5. Pricing FAQ：價格是否為最後價格、車馬費、外縣市、訂金與付款等問題。

Desktop 可提供 Table 作為次要比較檢視，但不作為唯一資訊架構；Mobile 以 Cards／Sections 為主。

## 待確認事項

- 各服務正式的起始價格或區間價格。
- 是否有統一的加急費規則。
- 特殊案件是否適用三段訂金級距，以及例外案件的付款方式。
- 綠界正式環境啟用時程與可用付款方式。
- 預約訂金的取消／退款／改期規則、尾款收取時間與收取方式。
- 是否有特殊案件需要預付款。
- 改期費與取消條件。
- 退款是否依不同服務類型而異。
- 各服務交付內容與完成時間是否影響修改／取消費用。
